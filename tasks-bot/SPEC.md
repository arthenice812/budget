# ТЗ: личный и командный планировщик задач в мессенджере

Версия документа: 2026-10-07 · эталонная реализация: `tasks-bot/` (Telegram-бот на Cloudflare Workers + D1), версия кода `faf5972`.

Документ описывает **всё поведение продукта** так, чтобы его можно было перенести в другую платформу (другой мессенджер, веб-приложение, мобильное приложение, корпоративный таск-трекер) без потери функций. Требования сформулированы независимо от Telegram; где поведение завязано на конкретную платформу, это отмечено пометкой **[TG]** и описан смысл, который нужно сохранить.

Обозначения: **FR** — функциональное требование, **NFR** — нефункциональное, **AC** — критерий приёмки. «Сегодня» во всех примерах — среда 30.09.2026, 12:00 по часовому поясу продукта (Europe/Moscow), если не сказано иное.

---

## 1. Назначение и принципы

**Проблема.** Задачи записываются «в Избранное» и в рабочие чаты, теряются, дедлайны забываются. После собраний детали не доносятся до задачи.

**Решение.** Список дел внутри мессенджера, которым человек и так пользуется весь день:
- задача записывается одной фразой на естественном языке — срок, время, повтор и важность извлекаются из текста;
- продукт сам напоминает по личному рабочему графику и не даёт задачам «лечь на дно»;
- задачи можно ставить друг другу в общих проектах (руководитель ↔ сотрудник);
- встречи подтягиваются из календаря, к ним готовятся задачами.

**Принципы, которые нужно сохранить при переносе:**
1. **Ноль обязательных полей.** Задача создаётся из любого текста; всё остальное — по желанию.
2. **Естественный язык прежде форм.** Любое действие доступно и словами, и кнопками.
3. **Одна строка кнопок под карточкой.** Остальное спрятано в «Срок» и «Ещё» — интерфейс не громоздкий.
4. **Всё отменяемо.** Удаление, «готово», перенос всего на завтра, правка подробностей — с кнопкой «Вернуть».
5. **Не спамить.** Сообщения только в рабочие часы человека, не дублировать, старые напоминания удалять.
6. **Понятные ошибки.** Бот никогда не молчит и не отвечает «не найдено» без объяснения, почему.

## 2. Глоссарий

| Термин | Значение |
|---|---|
| Задача | Единица работы: название, срок, подробности, чек-лист, повтор и т. д. |
| Карточка | Сообщение/экран с одной задачей и кнопками действий |
| Срок (due) | Дата и необязательное время, к которому задача должна быть сделана |
| Дата начала (start) | Когда браться за задачу; до неё задача не «горит» |
| Проект | Общая папка задач нескольких людей |
| Автор (owner) | Кто создал задачу |
| Исполнитель (assignee) | На ком задача сейчас |
| Повтор | Правило, по которому задача после «Готово» переносится на следующую дату |
| «Жду ответа» | Состояние задачи, которая стоит из-за другого человека |
| «Не отстану» (nag) | Режим настойчивых напоминаний каждые N минут |
| Главное (focus) | До 3 задач дня, отмеченных ⭐ |
| Рабочий график | Начало/конец рабочего дня и выходные конкретного человека |
| Закреплённый список (dash) | Постоянно обновляемое сообщение «📌 Мои задачи» вверху чата |
| Доска | Задачи по колонкам-срокам (веб-доска и доска в чате) |
| Встреча | Событие из подключённого календаря (ICS) |

## 3. Роли и доступ

| Роль | Права |
|---|---|
| Владелец инсталляции | Разворачивает продукт, задаёт настройки, технически имеет доступ к базе |
| Пользователь | Свои задачи, проекты, где он участник |
| Создатель проекта | + переименовать, удалить проект |
| Участник проекта | Видит все задачи проекта, может ставить задачи участникам, менять статусы, срок, подробности; может выйти |
| Автор задачи | + удалить задачу, перенести её в другой проект, поставить её нескольким и менять их состав |
| Исполнитель копии общей задачи | Отмечает выполнение, дописывает подробности, переносит свой срок; не может переназначить копию или перенести в другой проект |

**FR-ACC-1.** Режим закрытой инсталляции: если задан список разрешённых пользователей (`ALLOWED_USERS`), новые пользователи попадают в продукт **только** по ссылке-приглашению в проект; остальным — «Это личный бот. Твой ID: …».
**FR-ACC-2.** Ссылка-приглашение многоразовая, у каждого проекта своя, не меняется со временем.
**FR-ACC-3.** Личные задачи видит только их автор/исполнитель. Задачи проекта видят все участники проекта. Исключение — общая задача (§ 6.15): копию видит только её исполнитель, а саму общую задачу не видят те, у кого есть своя копия (чтобы не было дублей).
**FR-ACC-4.** Действие с задачей, к которой у пользователя больше нет доступа, отвечает объяснением: «Эта задача тебе больше не доступна: её передали другому или убрали из проекта» / «Этой задачи больше нет — её удалили».

## 4. Модель данных

Платформо-независимая модель. В эталонной реализации редко запрашиваемые поля задачи хранятся в JSON-колонке `data`.

### 4.1 Пользователь

| Поле | Тип | Описание |
|---|---|---|
| id | ID в мессенджере | |
| name, username | строка | |
| schedule | `{from:'HH:MM', to:'HH:MM', weekdaysOnly:bool}` \| null | рабочий график (§ 8) |
| focus | `{date, ids:[≤3]}` | главное на сегодня |
| calendar | `{url, lastSync, signature, error?}` \| null | подключённый ICS |
| dashMessageId | ID сообщения | закреплённый список |
| служебные отметки | даты | `lastMorning`, `lastEvening`, `lastWeekly`, `lastNag`, `nagMute`, `lastMeetWeek`, `calSent{}` — чтобы не отправлять дважды |
| awaiting | `{kind, taskId?, at}` | чего бот ждёт следующим сообщением (§ 6.9) |
| undo-буферы | | `trash` (удалённая задача), `undoDetails`, `lastBulk` (массовый перенос) |
| blocked | bool | пользователь заблокировал бота — ему ничего не шлём |

### 4.2 Проект
`id, name (≤40), owner, inviteCode (8 символов), members: Set<userId>, created`.

### 4.3 Задача

| Поле | Тип | Описание |
|---|---|---|
| id | целое, сквозная нумерация | показывается как `#12`, открывается `/t12` |
| title | строка ≤200 | |
| owner, assignee | userId | |
| project | projectId \| null | |
| done, doneAt | bool, дата | дата завершения обязательна для выполненных |
| due | `{date:'YYYY-MM-DD', time:'HH:MM'\|null}` \| null | |
| start | `{date, time:null}` \| null | дата начала |
| high | bool | 🔥 важная |
| nag | bool \| undefined | «не отстану»; по умолчанию включено для важных |
| repeat | см. 4.4 | |
| lastDone | `{due, date, checklist}` | для отмены случайного «Готово» у повторяющейся |
| history | даты выполнений (≤60) | |
| notes | `[{at, by, text}]` | подробности; текст может быть многострочным |
| checklist | `[{text, done}]` (≤50) | |
| files | `[{type, id, name}]` | вложения (ссылки на файлы в хранилище мессенджера) |
| status | `todo\|doing\|review` | статус в проекте |
| waiting | `{since, check}` | «Жду ответа»: с какой даты и когда спросить |
| meeting | `{h, uid, title, start, prep?}` | привязка к встрече |
| remindAt | `{date,time}` | отложенное напоминание («+1 час», «вечером», «завтра утром») |
| rem | `{at, h1, due, d<HH:MM>}` | что уже напомнено (идемпотентность) |
| ambig | `{raw, time}` | неоднозначность «10.11 — дата или время» |
| createdAt, reviewedAt | даты | для «залежавшихся» |
| hidden-for-user | множество userId | выполненная чужая задача скрыта из списка этого пользователя |
| group | `{kids:[{uid, id, done}]}` | только у общей задачи (§ 6.15): исполнители, id их копий и отметка «сделал(а)»; у общей `assignee = owner` |
| parent | taskId | только у копии общей задачи: id общей; `owner` = автор общей, `assignee` = исполнитель |

### 4.4 Повтор (repeat)

```
{ unit: 'day'|'week'|'month'|'year', n: 1..99,
  wd?: [0..6],            // дни недели (0 = вс) для недельных
  md?: 1..31, last?: true, // число месяца / последний день
  nth?: 1..4|-1, nwd?: 0..6, // «во второй четверг», «в последнюю пятницу»
  wday?: 1|-1,            // первый / последний РАБОЧИЙ день месяца
  until?: 'YYYY-MM-DD' }  // повторять до даты
```

### 4.5 Встреча (кэш календаря)
`userId, key (стабильный хэш uid+дата+время), uid, start, end, title, link, location, recurring`.

### 4.6 Служебное
- Производственный календарь по годам (строка из 365/366 символов «0/1», источник isdayoff.ru).
- Отметка последнего запуска планировщика (для `/status`).
- Связь «сообщение ↔ задача» (чтобы ответ на карточку относился к задаче), хранится 90 дней.

## 5. Интерфейс

### 5.1 Главное меню (всегда видно) [TG: reply keyboard]
Две строки по три кнопки:
```
[📋 Задачи] [⭐ Главное] [📅 Встречи]
[📁 Проекты] [🗂 Доска] [❓ Помощь]
```
**FR-UI-1.** Меню переотправляется само при изменении его версии и по команде `/menu`. Старые подписи кнопок продолжают работать.

### 5.2 Карточка задачи
Формат:
```
📌|🔥|✅ <Название>  #id
📅 срок (относительно: «сегодня 15:00», «завтра», «пт, 2 окт»)
▶️ начать: …          (если есть дата начала)
🔁 правило повтора     (если есть)
📁 проект · 👤 исполнитель · от автора   (если общий)
👥 Анна ✅ · Петя ⏳ — 1/2   (у автора общей задачи)
👥 общая задача        (у исполнителя на копии)
🏷 статус             (в проекте)
⏳ жду ответа с … — спрошу …
🗓 к встрече «…» — когда
Чек-лист 1/3: ☐/☑ пункты
📝 Подробности: — строки
↩️ Ответь на карточку — допишу детали или перенесу срок
```
**Кнопки (одна строка):** `✅ Готово` · `📅 Срок` · `☑ 1/3` (если есть чек-лист) · `☰ Ещё`.
После создания задачи дополнительно: до 3 последних проектов кнопками `📁 Название`; в проекте с несколькими участниками — кнопки с именами («кому поставить»), а если участников больше двух — «👥 Нескольким…».
На напоминаниях вместо `📅 Срок` — `🔔 +1 час` и `🔔 Завтра`.

**Режимы клавиатуры карточки** (одна карточка перерисовывается на месте):

| Режим | Кнопки |
|---|---|
| Срок | Сегодня · Завтра · +неделя · ✏️ Своя дата · Без срока / ⏭ Пропустить раз (у повторяющихся) · ▶️ Начать… · 🔁 Повтор · ← Назад |
| Ещё | 🔁 Повтор · 📁 Проект (автор; не у общей и не у копии) · 👤 Кому (в общем проекте; у общей — «👥 Кому (N)», у копии нет) · 🔥 Важно/⬇️ Не важно · 🔔 Не отстану/🔕 · ⏳ Жду ответа/Уже не жду · 🗓 К встрече · ✏️ Подробности · 🏷 Статус (в проекте) · 📎 Файлы (N) · 🗑 Удалить (автор) · ↩️ Отменить «Готово» (если было) · ↩️ Вернуть удалённые подробности (если есть буфер) · ← Назад |
| Повтор | Каждый день · По будням · Каждую неделю (день недели из срока) · Раз в 2 недели · Каждый месяц (число) · Каждый год · 1-й рабочий день месяца · Последний рабочий день · ⚙️ Настроить подробно (веб-форма) · 🔁✖ Не повторять · ← Назад |
| Проект | список проектов (✔️ текущий) · ➕ Новый проект · Убрать из проекта (личная) · ← Назад |
| Кому | участники проекта (✔️ текущий, «(я)») · 👥 Нескольким… (если участников >2) · ← Назад |
| Нескольким | участники проекта кроме автора с ☐/☑ · ☑ Всем · ✅ Поставить (N) · ← Назад. Выбор сохраняется между нажатиями; один выбранный = обычное поручение; ноль — задача снова на авторе |
| Начать | ▶️ Сегодня · ▶️ Завтра · ✏️ Своя дата · Без даты начала · ← Назад |
| Статус | 📥 К выполнению · 🔨 В работе · 👀 На проверке · ✅ Готово · ← Назад |
| Жду ответа | Спросить завтра · Через 3 дня · Через неделю · ✏️ Свой день · ← Назад |
| К встрече | встречи на 14 дней вперёд (≤8, ✔️ текущая) · ✖ Не привязывать · ← Назад |
| Чек-лист | пункты ☐/☑ (≤10) · ← Назад |
| Удалить | 🗑 Да, удалить · Отмена |
| Залежавшаяся | 📅 Сделать на этой неделе · 👍 Ещё актуально · ✅ Уже сделано · 🗑 Удалить |
| Выполнена | ↩️ Вернуть в работу · 🗑 (автор — удалить; не автор — убрать из своего списка) |

**FR-UI-2.** Все подсказки после нажатия — всплывающие (≤200 символов), карточка перерисовывается на месте.

### 5.3 Закреплённый список «📌 Мои задачи»
Группы: ⭐ Главное сегодня → 🔴 Просрочено → 📍 Сегодня → 🔜 Завтра → 🗓 Неделя → 📆 Позже → ⏳ Жду ответа → 📥 Без срока → 📤 Поручено другим. В конце — «✅ Сделано сегодня: N · все выполненные — /done». Каждая строка — название, срок, ссылка `/tN`; у общей задачи — « 👥 n/N».
**FR-UI-3.** Обновляется после каждого изменения задач пользователя и раз в день (когда «завтра» становится «сегодня»). Пропал — `/pin`.

### 5.4 Распределение по колонкам (bucket)
Единое правило для списка, доски и сводок:
1. «Жду ответа» → **waiting**.
2. Нет срока и даты начала → **nodate**.
3. Срок прошёл (дата < сегодня, или сегодня и время прошло) → **overdue**.
4. Есть дата начала в будущем → по дате начала: завтра → **tomorrow**, ≤7 дней → **week**, иначе **later**; дата начала наступила → **today**.
5. По сроку: ≤ сегодня → **today**, +1 день → **tomorrow**, ≤7 дней → **week**, иначе **later**.
6. Выполненные → **done**.

Сортировка внутри: ⭐ главное → 🔥 важные → по сроку (дата, затем время; без времени — в конце дня) → по id. Выполненные — по дате завершения, новые сверху.

## 6. Функциональные требования

### 6.1 Онбординг
**FR-ON-1.** `/start`: справка «С чего начать» (3 шага с примерами), главное меню, вопрос о рабочем графике (§ 8), создание закреплённого списка.
**FR-ON-2.** `/start join_<код>`: вступление в проект, сообщение «🤝 Ты в проекте «X»» с подсказками, меню. Создателю проекта — «👋 Имя теперь в проекте «X» (всего участников: N)». Остальным участникам — ничего (чтобы общая ссылка в чате не спамила).
**FR-ON-3.** Уже существующим пользователям вопрос о графике задаётся один раз при следующем сообщении.

### 6.2 Создание задачи
**FR-CR-1.** Любой текст, не распознанный как команда, создаёт задачу. Первая строка — задача (с разбором срока и пр.), следующие строки — подробности; строки, начинающиеся с `-`, `–`, `—`, `•`, `*`, `[ ]`, `☐` — пункты чек-листа.
**FR-CR-2.** Пересланное сообщение → задача, в подробностях — «от кого переслано».
**FR-CR-3.** Фото/файл/видео/аудио с подписью → задача с вложением (подпись — текст задачи). Альбом (группа файлов) → одна задача. Файл ответом на карточку → прикрепить к задаче.
**FR-CR-4.** Голосовое → расшифровка (Whisper, русский) → задача; бот показывает «🎙 «расслышанный текст»». Ответ голосовым на карточку → дописать в подробности.
**FR-CR-5.** Префикс проекта: `Название проекта: текст` → задача в проект (если такой проект есть у пользователя; иначе обычная задача). Также `#проект`.
**FR-CR-6.** Упоминание `@Имя`/`@username` участника → задача поставлена ему, ему приходит «📨 Новая задача от …». Неизвестное имя → предупреждение «Не нашёл @… среди участников… Задача пока на тебе». Несколько упоминаний (`@Анна @Петя`) или слово «всем»/«для всех»/`@все` → общая задача (§ 6.15); без проекта — предупреждение «Чтобы поставить задачу нескольким, начни с названия проекта: Отдел: всем …».
**FR-CR-7.** Ответ на создание: «✅ Задача сохранена» + карточка. Предупреждения добавляются в начало:
- похоже на повтор, но правило не распознано («каждый …») → «⚠️ Похоже, задача регулярная, но я не понял, как повторять…»;
- несуществующая дата/время → «⚠️ «31 сентября» — такой даты или времени не бывает, поэтому срок не поставил…»;
- задача на сегодня/со временем, а планировщик не работает → предупреждение со ссылкой на `/status`.
**FR-CR-8.** Вступления «Задача:», «Напомни (мне)», «Напомнить», «Не забыть», «Добавь (задачу)», «Запиши», «Надо», «Нужно», «Важно:», «Срочно:» вырезаются из названия; «важно/срочно» ставят 🔥. Слово «Задача» без двоеточия/тире остаётся («Задача 1 сделать презентацию»).

### 6.3 Разбор естественного языка (сроки)

**FR-NL-1. Даты.**

| Ввод | Результат |
|---|---|
| сегодня / завтра / послезавтра | 30.09 / 01.10 / 02.10 |

| 10 числа | ближайшее 10-е |
| через 3 дня / 2 недели / месяц | от сегодня |
| через 30 минут / час / полчаса / 2 часа | дата и время от текущего момента |
| на следующей неделе | понедельник следующей недели (05.10) |
| в конце недели, до конца недели | пятница этой недели; в сб — воскресенье, в вс — сегодня |
| в конце месяца | последний день месяца |
| в следующем месяце, в начале месяца | 1-е число следующего месяца |

| Ввод | Результат |

| в 18, к 5 (в конце фразы или перед «с/у/и/на/по/для/про/около/перед/после/—») | 18:00, 17:00 |
| в 2…в 6 без «утра» | 14:00…18:00 (дневное время) |

| в 2 часа ночи | 02:00 |
| в 10 часов 30 минут | 10:30 |
| утром / днём / к обеду / в обед / после обеда / вечером / в полдень | 09:00 / 13:00 / 13:00 / 13:00 / 14:00 / 19:00 / 12:00 |
| только время без даты | сегодня, если не прошло; иначе завтра |

Числа, не являющиеся временем, не трогаются: «Купить 2 литра», «живу в 5 корпусе», «раз в 2 недели».

**FR-NL-3. Начало и дедлайн.** «Отчёт начать в среду, сдать в пятницу», «начать отчёт в понедельник, сдать в пятницу», «Презентация начать завтра дедлайн 10.10» → start + due; слова «сдать/дедлайн/срок» удаляются из названия; если дедлайн-день недели получился раньше начала, он переносится на ближайший такой день **после** начала.

**FR-NL-4. Повторы.**

| каждый день, ежедневно | day ×1 |

| по выходным | week, сб–вс |
| каждый понедельник, по вторникам и четвергам | week, wd |
| каждые 2 недели, раз в две недели (по четвергам / в четверг) | week ×2 (+wd) |
| каждую вторую неделю | week ×2 |
| каждый месяц, ежемесячно 1 числа, 25 числа каждого месяца | month, md |

Время повторяющейся задачи сохраняется при переносе («Витамины каждый день в 9:00»).

**FR-NL-5. Важность и «жду».** `!`, `!!`, `!!!`, «срочно», «важно», «asap» → 🔥. Начало «Жду …» → состояние «Жду ответа».

**AC-NL.** Все примеры из таблиц § 6.3 воспроизводятся автотестами (эталон: `test/parse.test.mjs`).

### 6.4 Действия с задачей
**FR-ACT-1. Готово.** Обычная → done, doneAt = сегодня, участникам — уведомление. Повторяющаяся → сохраняется `lastDone`, чек-лист сбрасывается, срок переносится на следующий раз (если `until` пройден — задача завершается); на карточке «↩️ Отменить «Готово»». Привязка к регулярной встрече переезжает к следующей встрече серии.
**FR-ACT-2. Вернуть в работу** (undo) и **отменить «Готово»** у повторяющейся (rundo — возвращает прежний срок и чек-лист).
**FR-ACT-3. Срок.** Сегодня/завтра (с сохранением времени у повторяющихся), +неделя, без срока, своя дата (бот ждёт текст 15 мин), пропустить раз (повторяющиеся). Ответ датой на карточку тоже переносит срок. Изменение срока сбрасывает отметки напоминаний.
**FR-ACT-4. Отложить напоминание:** «+1 час», «вечером» (время сверки), «завтра утром» (начало рабочего дня).
**FR-ACT-5. Удалить** — только автор; после удаления «↩️ Восстановить» (полное восстановление с тем же id). Исполнитель, если не автор, получает «🗑 Имя удалил(а) задачу».
**FR-ACT-6. Проект/исполнитель.** Сменить проект может только автор. При смене исполнителя новому — «📨 Имя поручил(а) тебе задачу», прежнему — «↩️ Имя передал(а) задачу … — она больше не на тебе». Убрать из проекта → исполнитель = автор, прежнему исполнителю — уведомление.
**FR-ACT-7. Статус** в проекте: todo/doing/review/done, участникам — уведомление.
**FR-ACT-8. Чек-лист:** отметка пунктов кнопками; прогресс «☑ 1/3».
**FR-ACT-9. Файлы:** кнопка присылает все вложения задачи.
**FR-ACT-10. Важно / Не отстану / Жду ответа / К встрече** — см. § 6.10, 6.11, 6.12.

### 6.5 Команды словами
| Фраза | Действие |
|---|---|
| `удали задачу про отчёт`, `отмени …`, `убери …`, `сотри …` | удалить; несколько совпадений — выбор кнопками (≤8) + «➕ Нет, это новая задача» |
| `готово отчёт`, `сделала …`, `выполнила …`, `закрой …`, `отметь …` | отметить выполненной (с «↩️ Ой, не выполнено») |
| `перенеси отчёт на пятницу 15:00` | перенести; без даты — подсказка с примером |
| `перенеси всё на понедельник` | перенести всё просроченное и сегодняшнее (с «↩️ Вернуть как было») |
| только дата (`в пятницу`) в течение часа после создания задачи | «Перенести «X» на …?» Да/Нет |
| `удали` / `готово` без названия | список задач кнопками |
| `удали проект Тест` | подтверждение удаления проекта |
| `создай проект Работа`, `новый проект` | создание проекта |
| `переименуй проект Тест в Отдел` | переименование |
| `график 10-19`, `график 9:30-18:30 без выходных`, `мой график` | рабочий график |
| `спросить в четверг` (после «Жду ответа» или ответом на карточку) | день проверки «Жду ответа» |

Поиск задачи по словам: совпадение по основам слов (первые 5 букв), сначала полные совпадения, затем частичные; `#12` / `/t12` / `12` — по номеру.

### 6.6 Ответ на карточку
| Ответ | Действие |
|---|---|
| любой текст | дописать в подробности; строки с «-» — в чек-лист; участникам — «💬 Имя дописал(а) подробности» |
| дата / повтор | перенести срок / сделать повторяющейся |
| `не повторять` | убрать повтор |
| `готово`, `удали`, `перенеси на …` | действие с этой задачей |
| `убери детали`, `удали подробности` | очистить подробности (с «↩️ Вернуть как было») |
| `удали чек-лист` | очистить чек-лист |
| `убери <слова>` | удалить одну строку подробностей/чек-листа с этими словами; несколько — выбор кнопками; ни одной — трактовать как команду поиска задачи |
| `спросить в четверг`, `уточнить через 2 недели` | «Жду ответа» с этим днём |
| файл | прикрепить |
| голосовое | расшифровать и дописать |

### 6.7 Редактирование подробностей
**FR-DET-1.** «☰ Ещё → ✏️ Подробности»: бот присылает текущие подробности одним блоком моноширинного текста (нажатие копирует), кнопки «📋 Скопировать текст» (если ≤256 символов), «🗂 Изменить на доске», «🗑 Очистить всё», «✖ Отмена». Формат: заметки строками, пункты чек-листа `- пункт`, отмеченные `- ✓ пункт`.
**FR-DET-2.** Следующее сообщение (в течение 10 минут и не ответом на другую карточку) **заменяет** подробности и чек-лист целиком. Отметки пунктов сохраняются по совпадению текста или по `✓`. Ответ: «✏️ Подробности обновлены» + «↩️ Вернуть как было».
**FR-DET-3.** Если подробности длиннее 3000 символов — править только на веб-доске.
**FR-DET-4.** Кнопки «✖ строка» для удаления отдельных строк (режим «Подробности»), с проверкой, что строка не сдвинулась.

### 6.8 Регулярные задачи
**FR-REP-1.** Следующая дата: для `wd` — ближайший подходящий день недели после текущего срока, при n>1 — с пропуском недель; day/week — +n дней/недель; month — то же число (или последний день, если месяц короче) через n месяцев; nth — n-й день недели месяца; wday — первый/последний рабочий день месяца по производственному календарю; year — +n лет. Пропущенные разы не копятся (следующая дата > сегодня).
**FR-REP-2.** «Настроить подробно» — форма как в календаре: вид (дни/недели/месяцы/годы), «раз в N», дни недели, варианты месяца (число / N-й день недели / последний день недели / последний день / первый рабочий / последний рабочий), «до даты»; строка «Что получилось» обновляется сразу.
**FR-REP-3.** «Сделать на неделе» у повторяющихся с датой начала сохраняет отступ «начать за N дней».
**FR-REP-4.** `/repeat` — список регулярных с правилом и следующей датой.

### 6.9 Ожидание следующего сообщения (awaiting)
Бот может ждать: дату (15 мин), дату начала (15 мин), название проекта (30 мин), новое название проекта (30 мин), подробности (10 мин), день «жду ответа» (15 мин), что подготовить к встрече, итоги встречи. Если пришло что-то явно другое (новая задача, ответ на другую карточку) — ожидание сбрасывается, сообщение обрабатывается обычно. Кнопка «Отмена» есть всегда.

### 6.10 Проекты
**FR-PRJ-1.** Создание: «📁 Проекты» → «➕ Создать проект» → название (≤40); или словами. После создания: как добавлять задачи, «👥 Позвать людей», «📋 Задачи проекта».
**FR-PRJ-2.** Приглашение: ссылка `…?start=join_<код>` и кнопка «👥 Позвать людей» (выбор чата для пересылки) [TG: switch_inline_query]. Одна ссылка — для любого количества людей.
**FR-PRJ-3.** Экран проекта: задачи по статусам (🔨 В работе → 👀 На проверке → 📥 К выполнению), выполненные за 7 дней; кнопки «👥 Позвать людей», «✏️ Переименовать» + «🗑 Удалить проект» (создатель) или «🚪 Выйти из проекта».
**FR-PRJ-4.** Переименование — только создатель; дубликат названия у пользователя — ошибка; участникам — «✏️ Имя переименовал(а) проект «A» → «B»»; задачи и ссылка-приглашение не меняются.
**FR-PRJ-5.** Удаление — только создатель; два варианта: «задачи оставить (станут личными у исполнителей)» / «удалить вместе с задачами»; участникам — уведомление.
**FR-PRJ-6.** Выход участника: его открытые задачи проекта, поставленные другими, возвращаются авторам; если вышел создатель — права создателя переходят другому участнику; если вышел последний — проект удаляется, задачи становятся личными.
**FR-PRJ-7.** Уведомления второй стороне (автор ↔ исполнитель) о: выполнении, переносе срока, новых подробностях, статусе, повторе, файле, удалении. Действующему лицу — не шлются.
**FR-PRJ-8.** Одну задачу можно поставить нескольким участникам — см. § 6.15.

### 6.11 «Жду ответа»
**FR-WAIT-1.** Включение: кнопка (завтра / через 3 дня / через неделю / ✏️ свой день), слово «Жду» в начале задачи, «спросить в четверг» ответом на карточку или сразу после включения.
**FR-WAIT-2.** Задача в колонке «⏳ Жду ответа», не считается просроченной, не участвует в «не отстану» и напоминаниях «на сегодня».
**FR-WAIT-3.** Утром в день проверки: «⏳ Пришёл ли ответ?» по каждой такой задаче (≤5), кнопки «✅ Пришёл» (снять ожидание) / «⏳ +3 дня» / «✏️ Другой день», и готовый текст вежливого напоминания для копирования. Без ответа — спросит завтра снова.

### 6.12 «Не отстану» и главное дня
**FR-NAG-1.** Включается вручную или автоматически для 🔥 важных. Когда срок наступил (для задач без времени — с первого слота «на сегодня»), каждые `NAG_EVERY` минут (30) в рабочие часы человека приходит **одно** сообщение со всеми горящими задачами (≤5): «🔔 Не отстану — это ещё не сделано», кнопки «✅ <задача>», «⏰ +1 час», «🔕 Сегодня больше не напоминать». Предыдущее такое сообщение удаляется.
**FR-FOC-1.** «⭐ Главное»: выбор до 3 задач кнопками (кандидаты: просрочено, сегодня, завтра, неделя, важные без срока), «Готово». Главные — наверху всех списков с ⭐, сбрасываются на следующий день.

### 6.13 Выполненные
**FR-DONE-1.** У каждой выполненной хранится и показывается дата завершения: `/done` (группировка по дням: «✅ сегодня / вчера / 5 окт», «· от Имя» / «· Имя» для общих), доска в чате (вкладка «✅ Готово»), веб-доска (колонка «Готово» за 30 дней, дата на карточке, сортировка по дате завершения), закреплённый список («Сделано сегодня: N»).
**FR-DONE-2.** «🧹 Очистить выполненное» (в `/done`, обеих досках) с подтверждением: свои выполненные удаляются насовсем; поставленные другими — скрываются только из своего списка (у автора остаются).
**FR-DONE-3.** Одна задача: 🗑 на карточке выполненной — автор удаляет, не автор скрывает у себя.
**FR-DONE-4.** Выполненные старше 120 дней удаляются автоматически раз в неделю.

### 6.14 Залежавшиеся
**FR-STALE-1.** Утром (с планом дня) — максимум одна задача без срока и без повтора, созданная/просмотренная ≥14 дней назад: «🧹 Лежит без срока больше двух недель. Ещё актуально?» с кнопками режима «Залежавшаяся».

### 6.15 Общая задача на нескольких
Цель — одна задача на нескольких людей без размножения задач у автора: автор видит одну строку с прогрессом, каждый исполнитель — свою задачу со своими напоминаниями и «Готово».

**Модель.** Общая задача автора (`group.kids`) + по копии на каждого исполнителя (`parent`). Копия — полноценная задача: свой срок, напоминания, чек-лист (отметки свои), «не отстану», «жду ответа».

**FR-GRP-1. Как поставить.**
- текстом: `Отдел: @Анна @Петя сверить акты до пятницы`; всем участникам кроме автора: `Отдел: всем сдать отчёт` (также «для всех», `@все`);
- кнопкой: на новой карточке или в «👤 Кому» → «👥 Нескольким…» → галочки / «☑ Всем» → «✅ Поставить (N)»;
- только для задачи в проекте и только автором; если задача уже была поручена одному, он остаётся в списке.
Ответ автору: «👥 Задача поставлена: Анна, Петя» + карточка. Каждому — «📨 Новая задача от Рина (общая — на N чел.)» + карточка копии.

**FR-GRP-2. Копия при создании** берёт у общей: название, подробности, чек-лист (все пункты не отмечены), срок, дату начала, важность, повтор, файлы. Владелец — автор, исполнитель — человек.

**FR-GRP-3. Видимость.** Автор видит только общую (в списке « 👥 n/N», в карточке — имена с ✅/⏳). Исполнитель видит только свою копию с пометкой «👥 общая задача». Остальные участники проекта видят общую задачу. Правило едино для списка, выполненного, доски в чате, веб-доски и экрана проекта.

**FR-GRP-4. Выполнение.**
- исполнитель отметил копию → автору «✅ Анна сделал(а) «…» (n/N)»; обычное уведомление «выполнено» по копии не шлётся;
- отметили все → общая закрывается с датой завершения, автору «🎉 Все сделали «…» (N/N) — задача закрыта»;
- исполнитель вернул копию в работу → общая снова открыта, прогресс пересчитан;
- автор закрыл общую сам → все незакрытые копии закрываются, исполнителям «✅ Рина закрыл(а) общую задачу «…» — делать больше не нужно».

**FR-GRP-5. Повторяющаяся общая.** Копия считается сделанной на этот раз, если её срок ушёл дальше срока общей. Когда сделали все → общая переходит на следующий раз, отметки сбрасываются, автору «🎉 Все сделали «…». Следующий раз: …». Автор, закрывший повторяющуюся общую, двигает только свою.

**FR-GRP-6. Правки автора доходят до копий:** название, срок, дата начала, важность, **новые** строки подробностей, **новые** пункты чек-листа. Удаление/правка старых строк и смена повтора в копии не переносятся. Уже выполненные копии не трогаются. Исполнителю — одно сообщение «✏️ Рина изменил(а) общую задачу» + карточка, и только если копия действительно изменилась (например, повторяющаяся копия, сама перешедшая на тот же срок, уведомления не получает). Правки исполнителя в своей копии остаются у него.

**FR-GRP-7. Состав.** «☰ Ещё» → «👥 Кому (N)» открывает те же галочки с текущим составом. Снятым — копия удаляется и (если не выполнена) «↩️ Рина снял(а) с тебя задачу «…»»; добавленным — новая копия и уведомление. Снять всех — задача снова только у автора.

**FR-GRP-8. Удаление.** Удалить может только автор, удаляется общая вместе со всеми копиями; исполнителям незакрытых копий — «🗑 Рина удалил(а) общую задачу «…»». «↩️ Восстановить» возвращает общую как **обычную** задачу автора (без копий и связи).

**FR-GRP-9. Ограничения.** Копию нельзя переназначить («исполнителей меняет автор») и удалить исполнителю; общую и копию нельзя перенести в другой проект (на доске выбор проекта и исполнителя заблокирован). Выход участника из проекта удаляет его копию и убирает его из состава.

**FR-GRP-10. Доски.** Веб-доска: на карточке в колонке «👥 n/N»; в листе задачи — «👥 Анна ✅ · Петя ⏳» у автора, «👥 общая задача» у исполнителя. API `state` отдаёт у задачи `group: [{name, done}] | null` и `shared: bool`.

**AC-GRP.** «Отдел: всем подготовить отчёт» (3 участника) → у автора одна задача «👥 0/3», у каждого своя; двое отметили → «2/3» и два сообщения автору; третий → «🎉 Все сделали», общая выполнена; автор перенёс срок до отметок → у всех трёх новый срок и по одному сообщению.

## 7. Встречи из календаря (ICS)

**FR-CAL-1. Подключение.** Пользователь присылает ICS-ссылку (Яндекс Календарь: календарь → ⚙️ → Экспорт → iCal). Сообщение со ссылкой **сразу удаляется** из чата (ссылка = пароль). Ответ: «✅ Календарь подключён! Встреч на ближайшие 7 дней: N» со списком и кнопками «📝» по встречам. Ошибка чтения — понятный текст, подключение не сохраняется. Отключение — «🔌 Отключить» (встречи удаляются из базы). Календарь только читается.
**FR-CAL-2. Разбор ICS.** Склейка перенесённых строк; `TZID`, `Z`, весь день (`VALUE=DATE`); `DTEND` или `DURATION`; `RRULE` FREQ=DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL, COUNT, UNTIL, BYDAY (в т. ч. `1TH`, `-1FR`), BYMONTHDAY; `EXDATE`; переносы `RECURRENCE-ID`; `STATUS:CANCELLED`; экранирование `\,` `\n`; ссылка на звонок из LOCATION/DESCRIPTION/URL (zoom, telemost, meet, teams…). Окно: от вчера до +35 дней (чтобы у встреч раз в 2 недели/месяц была «следующая»). Время переводится в часовой пояс продукта.
**FR-CAL-3. Обновление** раз в ~15 минут и по кнопке «🔄 Обновить». **В базу пишется, только если набор встреч изменился** (по подписи), иначе лимиты записи исчерпываются.
**FR-CAL-4. Ключ встречи** — стабильный хэш `uid|дата время`; используется в кнопках (≤64 байт).
**FR-CAL-5. Напоминания:** за 60 мин, за 15 мин и в момент начала (`MEET_REMIND`, по умолчанию `60,15,0`). Текст: «🔔 Через час / Через 15 мин / Начинается сейчас: Название», время, место, ссылка, подготовка (чек-лист), задачи к встрече кнопками. Если планировщик опоздал — только ближайшее напоминание (без «за час» после «за 15 минут»). Учитываются встречи сразу после полуночи.
**FR-CAL-6. Подготовка.** «📅 Встречи» → встреча → «Что подготовить?» → текст (пункты с новой строки) → задача «Подготовить: <встреча>» с чек-листом и сроком до начала; повторный ввод дописывает пункты. Или «📎 Добавить уже записанную задачу» → выбор из открытых задач.
**FR-CAL-7. Привязка задачи к встрече** с карточки («🗓 К встрече»): срок становится «до начала встречи», если был позже или отсутствовал. В «📅 Встречи» под встречей видны её задачи.
**FR-CAL-8. После встречи** (регулярной или с задачами): «🗒 Встреча закончилась», «Записать задачи по итогам» (каждая строка — задача, срок в строке; в подробностях «По итогам встречи …»), «➡️ Подготовить к следующей», список несделанных задач к встрече.
**FR-CAL-9.** В плане дня — «Встречи сегодня»; в первое рабочее утро недели — список встреч недели с кнопками подготовки.
**FR-CAL-10. Изоляция.** У общей встречи двух людей каждый видит в напоминании только свои задачи.

## 8. Рабочий график и автоматические сообщения

**FR-SCH-1.** При первом запуске: начало дня (7:00–12:00 кнопками), конец (начало+6…+11 ч), выходные («Пн–Пт, праздники — выходные» / «Работаю и в выходные»); «⏭ Потом» — общий график. Изменить — `/schedule` или `график 10-19` (минимум 2 часа).
**FR-SCH-2. Расчёт времён от графика `from–to`:**

| Сообщение | Время |
|---|---|
| ☀️ План дня | `from` |
| 📍 «Задачи на сегодня» без времени | `min(from+3ч, to−1ч)` и `to−1ч` |
| 🔔 «Не отстану» | с `from` до `to` |
| 🌙 Вечерняя сверка | `max(from+1ч, to−30мин)` |
| 📊 Итоги недели | последний рабочий день недели, время сверки (без выходных — воскресенье) |
| Отложить «вечером» / «завтра утром» | время сверки / `from` |

Без настроенного графика — общие настройки инсталляции (по умолчанию 09:00; 12:00 и 17:00; 09:00–21:00; 20:00; воскресенье 19:00).
**FR-SCH-3.** В выходные и праздники (по производственному календарю, если «пн–пт») — тишина. **Всегда** приходят: напоминания о задачах с точным временем и о встречах.
**FR-SCH-4. План дня:** просрочено, на сегодня, встречи сегодня, важное без срока, кнопки выбора главного; одно сообщение; затем — залежавшаяся задача и «Пришёл ли ответ?».
**FR-SCH-5. Задачи со временем:** за час — «⏰ До срока 1 час» (если до срока ≥45 минут и задача поставлена заранее, не «через 30 минут»; не для повторяющихся), при опоздании — «До срока 50 мин»; в срок — «⏰ Время пришло!» (если опоздание <6 часов). Кнопки «🔔 +1 час», «🔔 Завтра».
**FR-SCH-6. Задачи на сегодня без времени:** «📍 Сегодня срок» в каждом слоте (не для «жду ответа»; не для слотов, прошедших до создания задачи).
**FR-SCH-7. Вечерняя сверка:** главные задачи дня — «✅ сделано / ⏩ на завтра» по каждой; «⏩ Всё несделанное — на завтра (N)» одной кнопкой с «↩️ Вернуть как было».
**FR-SCH-8. Итоги недели:** сделано за неделю, что зависло (просрочено), что на следующей неделе.
**FR-SCH-9. Идемпотентность:** отметка «отправлено» записывается **до** отправки; сбой не приводит к повтору.

## 11. Нефункциональные требования

**NFR-1. Лимиты бесплатной платформы** (эталон: Cloudflare Workers Free + D1): 100 000 запросов/сутки, 10 мс CPU и ~50 подзапросов на запуск, 5 млн прочитанных и 100 тыс. записанных строк в сутки. Требования:
- планировщик каждые 5 минут читает **только открытые задачи** (индекс по `done`) и встречи по времени (индекс по `start`);
- календарь пишется в базу только при изменении;
- задача сохраняется **дифференциально** — только изменённые поля (`json_set`/`json_remove`);
- бюджет запросов на запуск: если не помещается — работа откладывается на следующий запуск (5 мин), а не теряется;
- снимки для дифференциального сохранения строятся лениво, форматтеры часового пояса кэшируются.
Ориентир ёмкости: ~15–20 активных пользователей на бесплатном тарифе (первым упирается CPU планировщика), до ~120 по записи и ~350 по чтению.

**NFR-2. Конкурентность.** Одновременные изменения одной задачи из чата, доски и планировщика не затирают друг друга (дифф по снимку на момент чтения).
**NFR-3. Надёжность.** Любая ошибка обработки → пользователю ответ «что-то пошло не так» (кнопка не «крутится»), в лог — стек. Повторная доставка того же обновления игнорируется (по update_id). Пользователь, заблокировавший бота, помечается и пропускается. Ошибка 429 — пауза и одна повторная попытка. Если база не приняла необязательный индекс — продукт работает без него.
**NFR-4. Время.** Один часовой пояс инсталляции (`TIMEZONE`); все даты — локальные строки `YYYY-MM-DD`/`HH:MM`; производственный календарь загружается раз в день на текущий и следующий год, при недоступности — сб/вс.
**NFR-5. Ограничения мессенджера** [TG]: текст ≤4096 (обрезка с «…»), всплывающая подсказка ≤200, данные кнопки ≤64 байт, ≤100 кнопок, HTML-разметка только из разрешённых тегов с экранированием `<>&`, названия в кнопках укорачиваются.
**NFR-6. Приватность.** Данные — в базе владельца инсталляции (не в мессенджере). Ссылка календаря удаляется из чата. Сообщения о чужих задачах — только участникам. Владелец инсталляции технически может читать базу — пользователей нужно об этом предупредить.
**NFR-7. Безопасность.** Вебхук принимает запросы только с секретным заголовком; веб-доска — только с валидной подписью initData (HMAC от токена бота, не старше 7 дней); на API — белый список действий; проверка прав на каждую задачу/проект.
**NFR-8. Тексты** — на «ты», короткие, с эмодзи-маркерами; без технического жаргона.

## 12. Критерии приёмки (сквозные сценарии)

1. **Запись и напоминание.** «Позвонить в банк завтра в 11» → карточка «завтра 11:00»; в 10:00 — «⏰ До срока 1 час» с «+1 час/Завтра»; в 11:00 — «Время пришло!»; ни одно не приходит дважды.
2. **После собрания.** Ответ на карточку «уточнить счёт\n- запросить акт» → подробности + чек-лист 0/1.
3. **Регулярная.** «Отчёт в последний рабочий день месяца» → дата с учётом праздников; «Готово» → следующий месяц; «Отменить «Готово»» возвращает прежнюю дату.
4. **Команда.** Руководитель ставит «Отдел: @Рина сверить акты до пятницы» → Рине уведомление; Рина жмёт «Готово» → руководителю уведомление; в /done у обоих с датой.
4a. **Общая задача.** См. AC-GRP в § 6.15.
5. **Общая ссылка.** 6 человек вступают по одной ссылке → создателю 6 сообщений, остальным — ни одного.
6. **График.** Сотрудник с 10–19 пн–пт получает план в 10:00, «на сегодня» в 13:00 и 18:00, сверку в 18:30, итоги в пятницу, в субботу и праздник — ничего; сотрудник без графика — по общему.
7. **Жду ответа.** «Жду договор от юристов» → «спросить в четверг» → в четверг утром «Пришёл ли ответ?» с текстом напоминания.
8. **Встреча.** Встреча 15:00 → напоминания 14:00, 14:45, 15:00; подготовка и привязанные задачи в напоминании; после — «по итогам».
9. **Опечатки.** «31 сентября» → «такой даты не бывает», задача не создаётся.
10. **Выполненное.** Очистка удаляет свои, скрывает чужие; у автора чужие остаются.
11. **Доска.** Перетаскивание «Позже → Завтра» меняет срок; правка подробностей сохраняется при закрытии «Назад».
12. **Нет «мёртвых» кнопок.** Неделя работы по расписанию (каждые 5 минут) с нажатием каждой пришедшей кнопки тем, кому она пришла: ни одна свежая кнопка не отвечает «не найдено/устарело»; ни в одном тексте/кнопке нет `undefined`, `NaN`, `null`, `[object`, `Invalid Date`.
13. **Нагрузка.** Сутки работы 3 пользователей с годом истории: нет полных просмотров таблиц задач/встреч в планировщике, <2000 записей и <40 000 чтений на человека.

Эталонные автотесты: `tasks-bot/test/*.test.mjs` (97 тестов: разбор, сценарии, проекты, календарь, график, надёжность, нагрузка, веб-доска в Chromium).

## 14. Перенос данных

Таблицы для экспорта: `users (id, name, username, data JSON)`, `projects (id, name, owner_id, code, created)`, `members (project_id, user_id)`, `tasks (id, owner_id, project_id, assignee_id, done, done_at, data JSON)`, `events` (кэш, переносить не обязательно), `meta` (производственный календарь — не обязательно). Поля `data` соответствуют § 4. Ссылки-приглашения сохраняют работу, если перенести `projects.code`. Вложения хранятся как идентификаторы файлов мессенджера — при смене мессенджера их нужно скачать и перезалить.

## 15. Известные ограничения и бэклог
- Один часовой пояс на всех пользователей.
- Бот работает только в личной переписке (не в группах).
- Календарь — только чтение (ICS), без записи встреч.
- Веб-доска в некоторых сетях требует VPN (есть доска в чате).
- Идеи: задачи из рабочих чатов командой, «сколько свободно сегодня», запись в календарь, личный часовой пояс, автоматические чаты для сборов на подарки.
